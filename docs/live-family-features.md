# 실제 가족 기록과 성격 대화

기존 색상, 카드, 둥근 모서리와 탭 구성을 유지하며 고정된 예시 수치를 제거했다.

## 가족 활동

- 가족 퀘스트는 한국 시간 월요일 00:00부터 다음 월요일 전까지 2개다.
- 마음 나눔: 현재 가족 구성원 모두가 그 주에 공개 마음 기록을 하나 이상 작성하면 완료된다. 같은 사람의 글을 여러 번 세지 않는다. 카드에서 글 작성으로 연결된다.
- 한 컷: 그 주 가족 사진이 하나 이상 저장되면 완료된다. 카드에서 사진첩으로 연결된다.
- 두 퀘스트는 실제 Firestore 기록에서 계산한다. 새로고침과 중복 클릭으로 보상을 반복 적립하지 않는다. 해당 기록을 삭제하면 진행도와 점수도 다시 계산된다.
- 패밀리 무드: 오늘 기록한 각 구성원의 가장 최근 직접 선택한 감정 중 `기쁨`의 비율. 기록이 없으면 `기록 전`이다. 가족의 심리 상태를 진단하는 점수가 아니다.
- 패밀리 에너지: 이번 주 공개 글/사진 각각 10점, 해당 게시물에 현재 남은 좋아요 2점, 실제 완료된 돌봄 5점, 완료된 주간 퀘스트 각각 40점. 매주 새로 집계한다.
- 일일 퀘스트: 오늘 돌봄, 오늘 감정 기록, 오늘 공개 이야기 작성. 각 작업 화면으로 연결된다. 기존의 출석 버튼은 실제 기능에 맞게 `오늘의 돌봄 확인`으로 표기한다.

## 마음 기록과 사진

공개 마음 기록 작성자에게만 수정/삭제 메뉴를 표시한다. 수정은 마음/본문/수정 시각만 허용한다. 생성 시각, 작성자, 좋아요는 보존한다. `Backend/firestore.rules`에 서버 측 작성자 검사를 추가했다.

사진첩 목록, 상세, 접근성 문구와 댓글에는 저장된 작성자 이름을 표시한다. 역할 기본 얼굴은 단색 사람 아이콘으로 대체했고 사용자가 올린 프로필 사진은 계속 표시한다.

## 강아지 성격

기다림, 새 친구, 귀가 인사, 새 장난감에 대한 4문항의 각 3개 선택지를 저장한다. 저장 위치는 `families/{familyId}/pet/profile.personalityProfile`이다. 답변은 `version`, `answers`, `summary`로 저장한다.

매 대화 요청 전에 최신 반려견 프로필을 읽어 `/pet-chat`에 이름과 네 답변을 전달한다. 서버는 각 문항의 행동 관찰을 말투 지침으로 바꿔 Gemini 시스템 프롬프트에 반영한다. 캐릭터 이미지 생성은 기존 성격 키를 사용한다. 반려견 설정에서 테스트 후 저장하면 대화에 적용된다.

## 화면 구분

`오늘의 감정`에는 `나의 감정 기록하기`를 두고 패밀리 무드 계산 기준을 설명한다. `가족 활동`에는 패밀리 에너지와 공개 `가족 이야기` 작성 버튼을 둔다. MIRA 인사이트는 고정 질문 없이 대화 말풍선과 하단 입력창을 사용한다. `살펴볼 신호`는 설명을 왼쪽, 수치를 일정한 오른쪽 열에 정렬한다. 온보딩에는 브랜드 이름의 뜻과 한국어 문구를 표시한다.

## MIRA 인사이트

`POST /insight-chat` → 로컬 Ollama `POST /api/chat`으로 연결한다. 최대 최근 12개 대화 메시지와 가족 프로필/최근 공개 글을 전달한다. 프로필 수정의 `좋아하는 것과 나의 성향`에서 가족이 직접 취향을 등록할 수 있다. 생일은 등록된 값만 사용한다. 비공개 감정 일기 원문과 사진 바이트는 인사이트 컨텍스트에 포함하지 않는다. 대화 기록은 현재 화면 세션 동안 유지하며 앱 재시작 후에는 초기화된다.

`Backend/ai-server/.env`의 선택 설정:

```dotenv
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3:4b
```

```powershell
ollama pull qwen3:4b
cd Backend/ai-server
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Ollama와 AI 서버가 실행 중이어야 인사이트가 응답한다. 사진 분석/강아지 대화는 기존 Gemini 키를 사용한다. 캐릭터 이미지 생성은 기존 Colab 서버를 사용한다.

## 확인

- `Backend/ai-server`: `python -m pytest -q` (대화 성격 전달/검증, Ollama 문맥/히스토리 전달, 제공자 오류 응답).
- `Frontend/mira`: `flutter analyze --no-pub`, `flutter test --no-pub` (주간 경계, 중복 참여, 빈 기록, 최신 감정, 비공개 데이터 제외, 성격 저장/퀴즈, 기존 모바일 레이아웃).
- Windows 한글 경로 환경에서는 Flutter SDK와 프로젝트의 영문 드라이브 별칭 및 영문 TEMP/TMP 경로를 사용한다.
- 실제 Firebase에서 수정/삭제하려면 `firebase deploy --only firestore:rules --project mood-12672`가 필요하다.
- Ollama API 형식: https://docs.ollama.com/api/chat

## 돌봄 인계 범위

이 PR에는 돌봄 배정 서비스, 완료 처리, 돌봄 카드 변경과 Colab 코드 변경을 포함하지 않는다. 기존 Cloud Functions 방식은 유지되며 현재 돌봄 연결 문제는 별도 담당자가 해결해야 한다. 운영 Firebase에는 앞선 작업의 직접 저장 방식 돌봄 규칙이 이미 배포되어 있어 저장소 규칙과 차이가 있다. 후속 담당자가 운영 규칙과 구현을 함께 맞춰야 한다.
